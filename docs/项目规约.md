# 项目规约

适用范围：虚拟伴侣应用（本仓库）。所有代码与提交均需符合本规约。

---

## 一、核心原则

### 1.1 OCP 的落地方式

开闭原则的本质是**识别变化的轴，只在轴上开接口**，而不是到处抽象。

判定规则（可执行、可 review）：

> **接口只在存在第二个实现或测试替身时才建。**

### 1.2 反对过度抽象

不为"未来可能需要"建抽象。三行相似代码优于一个过早的抽象。

任何新增抽象必须能回答：**它的第二个实现在哪？** 答不上来就不建。

---

## 二、真实扩展轴

本项目只有两条轴需要接口：

| 轴 | 现在 | 第二实现 | 接口 |
|---|---|---|---|
| LLM Provider | DeepSeek | 换厂商；**测试需要 mock** | ✅ `ChatProvider` |
| MemoryStore | IndexedDB | V2 上云；**测试需要内存实现** | ✅ `MemoryStore` |
| 情绪 / 摘要 / Prompt 组装 | 各一个实现 | 无 | ❌ 不建接口 |
| 存储介质细分 | 无 | 无 | ❌ 不建接口 |

V1 只允许存在这两个接口。

## 三、目录结构与依赖方向

```
src/
  core/                     纯逻辑，零 IO，可在 Node 直接跑
    llm/ChatProvider.ts       接口（Port）
    llm/protocol.ts           消息 / 流式事件类型
    memory/types.ts           实体类型
    memory/MemoryStore.ts     接口（Port）
    memory/extract.ts         抽取协议 + ops 应用（纯函数）
    memory/compose.ts         PromptComposer（纯函数）
    memory/summarize.ts       摘要（纯函数）
  adapters/
    llm/deepseek.ts           implements ChatProvider
    storage/idb.ts            implements MemoryStore
    storage/inmemory.ts       测试替身
  features/                  chat / persona / settings
  app/                       React 入口、路由
  composition/root.ts        组装根：全项目唯一 new 具体实现的地方
```

依赖方向规则：

1. `core` **不 import** 任何 adapter、React、浏览器 API
2. `adapters` 只依赖 `core` 的接口
3. `features` 只依赖 `core` 接口，不直接依赖 `adapters`
4. 只有 `composition/root.ts` 知道具体实现

扩展方式：**加一个 adapter + 组装根换一行，`core` 一行不改。**

---

## 四、明确不用的模式

- 单例
- 抽象工厂
- DI 容器
- 事件总线 / 观察者
- 装饰器链
- Repository + UnitOfWork 全家桶
- 任何**只有一个实现**的 interface

---

## 五、工程规约

| 项 | 规约 |
|---|---|
| TypeScript | `strict` + `noUncheckedIndexedAccess` |
| 边界校验 | LLM 返回值是不可信边界，必须校验。手写 guard，不引 zod |
| 错误处理 | `core` 内禁止 catch 后静默吞掉 |
| 命名 | 接口不加 `I` 前缀；实现类用 `XxxAdapter` |
| 测试 | `core` 必须单测；`adapters` 各一个集成测试；`features` 不写组件测试 |

---

## 六、Git 规约

| 项 | 规约 |
|---|---|
| 默认分支 | `main` |
| 工作分支 | `feat/*`、`fix/*`，合并后即删，不使用复杂 flow |
| 提交信息 | Conventional Commits，如 `feat(memory): 事实 KV 覆盖式更新` |
| 提交拆分 | 功能提交与变更日志提交**分开两个提交** |
| CHANGELOG | 每条变更必须记录**回滚条件** |
| 开发节奏 | TDD：先写测试再实现 |
| 提交批准 | 不自动提交，每次提交需明确批准 |

---

## 七、提交前检查清单

- [ ] `core` 中没有新增对 adapter / React / 浏览器 API 的 import
- [ ] 没有新增"只有一个实现"的 interface
- [ ] LLM 返回值已做守卫校验
- [ ] `core` 新增逻辑有对应单测
- [ ] 功能提交与变更日志提交分离
- [ ] CHANGELOG 条目包含回滚条件
