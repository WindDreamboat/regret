# 虚拟伴侣自适应进化 — V1 决策纪要

> **状态**：已决策。**V1 不执行自适应进化**。
> **决策日期**：2026-10-04
> **取代**：`V1记录期规范.md`、`V1记录期规范修订.md`、`V1记录期规范v0.2.md`（三份迭代草稿，已删除；历史仍可经 git 追溯）
> **设计参考**：[虚拟伴侣自适应进化规范.md](./虚拟伴侣自适应进化规范.md)（保留，V1 不执行）

## 一、结论

V1 的目标是「给几个真实用户试用的最小产品」（需求文档第九节）。在该规模下：

1. 支撑「engagement 能否作为优化目标」这套判定的统计门槛约为**每月 7 万对话轮**（推导见 §三），远超 V1 规模，**架构上不可达**。
2. 因此 `engagement` **永久定位为守门信号**：越界触发回滚，不作为优化目标去追求更高。
3. per-user 自动固化、shadow A/B、opt-in 匿名上传端点、记录期及其开闸判定（C2/C3/C4）**V1 一律不实现**。

一句话：**记录期的唯一产出是"能不能开闸"，而 V1 的规模注定开不了闸——那就不必建这台机器。**

- **守门检测从"每轮实时"降为"离线/按需"**。V1 只报警不动作，逐轮判分是纯烧 token。

- shadow 生成（+10%~25% token，且少样本下永远出不了结论）
- opt-in 上传端点、C4 与漏斗门槛、C2/C3 开闸条件
- 账本（无自动变更则无账本）、原型库（并入 V2 人设模板库）

- `prototype_weights` 等"预留字段"——遵循规约「不为未来建抽象」，改为本纪要 §四 的触发条件

## 三、被否决的机制与依据（存档，供未来重启时复用）

### 3.1 规模门槛（以「总轮数 T」为口径）

```
窗口/月 = T ÷ ADAPT_INTERVAL × o × w
  T = 每月总对话轮数（外生变量）
  ADAPT_INTERVAL = 50（每 50 轮才产出一个窗口）
  o = opt-in 率，w = 窗口完成率
```

固定 `o = 10%`、`w = 70%`，要在 **3 个月**内攒够 300 个配对窗口（需 100 窗口/月）：

```
T × 0.10 × 0.70 ÷ 50 = 100  →  T ≈ 71,000 轮/月（约每天 2,400 轮）
```

**关键：门槛取决于总轮数 T，不取决于月活数 M。** 虚拟伴侣是重度长尾分布，500 个中度用户（每天 5 轮）≈ 5,000 个轻度用户（每天 0.5 轮）。V1「几个用户试用」的规模距此有 3~4 个数量级。

> 注：V1 曾误用 `M × o × a × w × 12`（`a` 被当成"每人每月触发一次"的比例），既多乘 12（年/月），又把"每 50 轮一次"的计数过程压成 0~1 比例，双重低估门槛。上式为修正后口径。

### 3.2 若未来重启，必须先修正的三处

若某天达到 §四 的触发条件，重启前**必须先补上**这三点，否则结论无效：

1. **候选来源必须预注册**：shadow 需要一个候选 θ' 与现状对照，但记录期不自动固化，θ' 由谁提出将直接决定 C2 在估计什么。随机扰动 → Δ 普遍很小 → 相关性被衰减 → **等价性检验系统性假通过**。
2. **窗口按用户聚簇 → 用有效样本量**：`N_eff = N / [1 + (m̄ − 1)·ICC]`，`m̄` 为每用户平均窗口数。作为参考（ICC = 0.1）：30 人各 10 窗 → `N_eff ≈ 158`；3 人各 100 窗 → `N_eff ≈ 27`。漏斗恰好奖励"少人多窗"，即 `N_eff` 最低的构成。
3. **完整窗口过滤会引入幸存者偏差**：中途流失者正是被策略伤害的人，剔除他们只会让结果偏乐观。应把**流失率按 arm 分开统计**当作负向信号，或按意向性分析（ITT）保留全部随机化单元。

### 3.3 予以保留的统计要求（重启时直接沿用）

- **C2 必须用等价性检验（TOST）**，`95% CI ⊂ (−ε, +ε)`，`ε = 0.15`（预注册 SESOI）。绝不能用「p > 0.05 即通过」——那是把"没测出害处"当成"无害"，样本越少越容易通过。
- **样本量不足一律按"不通过"处理**，不得因攒不够而放宽 ε。
- 测量误差须做衰减校正：`ρ_corrected = ρ_observed / √(r_gate × r_eng)`，可靠性 `r` 由重复采样实测。
- 数据须打 `judge_version` / `model_version` 标签，跨版本不可合并。

## 四、重新评估触发条件

**当满足任一条件时，重新评估是否启动记录期（B 路径）：**

- 月对话总轮数 `T ≥ ~7 万`；或
- 真实用户数达到数百且留存稳定。

在此之前，`engagement` 恒为守门信号，**不预留任何代码字段**（遵循《项目规约》第一节「反对过度抽象」）。

判定设为定期动作（如每季度对照本节一次），避免"记录期"变成不做决定的托词。
