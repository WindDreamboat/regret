## 1. C2：等价性证明

### 1.1 为什么 p > 0.05 是错的

`corr 不显著为负` 只说明"没测出害处"。样本越少越难拒绝原假设 → **样本不足会系统性地通过检验**。这等于把"没有证据有害"当成"有证据无害"。

等价性检验（TOST）反过来要求：**95% CI 完全落在 (−ε, +ε) 内**。样本不足 → CI 宽 → 通不过。方向才对。

### 1.2 修订后的 C2（两个形式）

**C2a（诊断量）**：ρ = corr(ΔG1, Δeng_immediate)，需 95% CI ⊂ (−ε, +ε)，**ε = 0.15**（预注册的 SESOI）。

**C2b（判定量，优先）**：反事实策略评估——"如果每次都采用 engagement 更高的那个候选，累计 ΔG1 是多少？"

C2b 更贴近真实决策：你要知道的不是"相关性多大"，而是"照着 engagement 选会受多大伤"。要求 CI 下界 > −δ_harm（默认 δ_harm = 每窗口 0.02 G1 单位，需校准）。

**C2b 可行的前提是 50/50 随机化。** 两个候选的 G1 都能算（都是离线打分），但 engagement 只有被展示的那个能观测。随机化让"哪个候选 engagement 更高"这个概率可从日志无偏估计 → 反事实才可估。**如果展示策略改成"挑你觉得更好的那个"，C2b 直接不可估。** 所以 50/50 随机化是硬需求，不是实现细节。

### 1.3 衰减校正（否则会假通过）

ΔG1 来自 LLM judge，自带噪声。测量误差会把 ρ 往 0 缩：

```
ρ_observed = ρ_true × √(r_gate × r_eng)
```

可靠性越低，ρ 越接近 0 → **等价性越容易假通过**。必须校正：

```
ρ_corrected = ρ_observed / √(r_gate × r_eng)     # CI 同比放大
```

r 从 §3 的重复采样得出。**这就是为什么重复采样是承重结构**——它不只是为了测 δ，它是 C2 不假通过的前提。

### 1.4 样本量（C4 由此反推）

Fisher z：SE = 1/√(N−3)。要 CI 半宽 ≤ 0.15 → N ≈ **175 个配对窗口**。
按 r_gate·r_eng ≈ 0.6 做衰减校正后放大约 1.29² → **N ≈ 300**。

### 1.5 判定后果（三条，第三条最关键）

- C2 通过 → engagement 可作优化目标（弱信号，需与其他信号加权）
- C2 不通过 → engagement **永久只能作守门信号**（越界回滚，不追求更高）
- **样本量攒不够 → 按"不通过"处理**——不能因为攒不够就放宽 ε

## 2. C4：派生值 + 收集端决策

C4 不再是拍脑袋的 `30 窗口 × 20 用户`，而是从 §1.4 反推的 **N ≥ 300 配对窗口**。

### 2.1 按"在哪里能回答"拆分

| 条件 | 本地可测 | 需跨用户 |
|---|---|---|
| C1（δ） | ✅ 重复采样即可 | — |
| C2（污染） | ⚠️ 单用户需 ~15,000 轮 | ✅ 实际必须 |
| C3（区分度） | ⚠️ 同上 | ✅ 实际必须 |
| C5（离线 eval） | ✅ | — |

**关键结论：C1/C5 本地可闭环；C2/C3 本质上跨用户。** 零采集下后者不可达。

### 2.2 数据来源三条路

| 路径 | 可行性 | 成本 | 证据强度 |
|---|---|---|---|
| **A 本地 only** | ❌ 不可达（单用户 15k 轮） | 0 | — |
| **B opt-in 匿名指标端点** | ✅ 前提已确认（+10% 可接受） | 端点 + 托管 + 隐私工程 | 强（真实用户） |
| **C 模拟用户队列** | ✅ 离线可跑，自己额度 | 一次性、可复现、零用户成本 | 中（见下） |

**推荐顺序：C 先跑（验证管线 + 抓严重污染），实测漏斗后再决定 B 的规模与是否分层。**

C 的真正优势不是便宜，是**可以构造已知 ground truth**：做一个"真正想要诚实反驳"的模拟用户，直接测 engagement 是否会把它推向谄媚。这是对着失败模式的定向测试，不只是算相关性。

局限要说清楚：**模拟的 engagement 不是真实 engagement**。C 能验证测量管线本身通不通、能抓出严重污染，但不能替代对真实人群的结论。用 C 决定要不要建 B，不要用 C 直接开闸。

### 2.3 B 的真实漏斗（先测，不要猜）

300 个**完成**的配对窗口 ≠ 300 次触发。中间三层衰减：

```
有效窗口/月 ≈ M × o × a × w × 12
  M = 月活
  o = opt-in 率
  a = 聊满 50 轮触发一次的比例
  w = shadow 窗口 20 轮内不流失的完成率
```

| 情景 | M | o | a | w | 窗口/月 | 攒够 300 |
|---|---|---|---|---|---|---|
| 乐观 | 2000 | 15% | 50% | 80% | ~1440 | <1 月 |
| 中性 | 500 | 10% | 40% | 70% | ~168 | ~2 月 |
| 悲观 | 100 | 8% | 30% | 60% | ~17 | **>17 月** |

**差 20 倍，现在猜没有意义。**

**Pilot（2–4 周，必做）**：只测 o、a、w 三个数，不测 C2（样本不够）。
反推时间线 **> 6 个月 → 重新评估 B 是否值得建**，不要硬拖。

### 2.4 BYOK 下的跨用户可比性（新暴露的问题）

开源 + BYOK → 用户用的模型、judge 各不相同。跨用户聚合 ΔG1 时，
GPT 用户与 Claude 用户的分数**不可比**，engagement 基线也可能不同。

三个选项：

| 方案 | 代价 | 评价 |
|---|---|---|
| 按模型分层，每层 300 | N 翻倍甚至更多 | 最严谨，最贵，早期扛不住 |
| **pilot 限定到 1–2 个推荐配置** | 结论只覆盖该配置 | **推荐**：先把结论做实，再谈泛化 |
| 模型作为协变量进回归 | 小样本下不稳 | 折中，留作后续 |

**推荐第二个。** 先在一个配置上把"engagement 会不会推向谄媚"这个问题回答清楚，
再扩展到多模型——那时每个新配置只需验证一致性，不必重跑完整 N。

### 2.3 零采集是架构约束，不是偏好

坚持零采集 → C4 不可达 → 自动固化**架构上不可能**。这时诚实的做法是明确放弃 per-user 自动固化，而不是让它永远停在"记录期"。

## 3. V1 是否跑 shadow

### 3.1 成本（用户付，云端 API）

每 50 轮跑一个 20 轮 shadow 窗口、窗口内 p=0.5 → 50 轮内多生成 10 次 → **+20% token**。
调参：窗口 10 轮 / p=0.3 → 约 +6%。
叠加重复采样（5% 触发、k=2）→ +5%。
**默认配置合计约 +10%——已确认为用户可接受。仍必须 opt-in。**

⚠️ **文案要说清"谁的 +10%"**：这是全量用户的均值，
**实际触发 shadow 的那些用户是 +20%~25%**。写成平均会让人觉得偷跑流量。

### 3.2 不跑的后果链

不跑 shadow → 无 Δ → C2/C3 不可计算 → 开闸表永远算不出来 → 记录期变成仪式。

**shadow 决策 = engagement 驱动的自动固化是否可能的决策。要么一起要，要么一起放弃。**

### 3.3 若坚持零采集

此时跑 shadow 无意义——付了成本也永远出不了结论。诚实的 V1 是：

- ✅ 事实层记忆检索（不参与优化，无风险）
- ✅ 守门指标实时检测（只报警，不动作）
- ✅ 显式反馈驱动的手动调整（稀疏但高信噪比）
- ✅ 发版级共享改进（你自己在离线 eval 上做）
- ❌ per-user 自动固化
- ❌ shadow 生成

## 4. schema 修订要点

在 v0.1 基础上补四条：

```jsonl
{"type":"shadow_turn","ts":"...","turn":312,
 "assignment_rand":{"seed":88213,"p":0.5,"shown":"cand"},   ← 新增：证明随机化被执行
 "judge_version":"g1-judge@2026.09",                        ← 新增：跨版本数据不可合并
 "model_version":"<provider>/<model>@<date>",               ← 新增：同上
 "cand":{"knobs":{...},"gates":{"G1":0.42,...}},
 "inc": {"knobs":{...},"gates":{"G1":0.55,...}},
 "engagement":{"immediate":{...},"delayed":{...}},
 "negative":{...},
 "window_complete":true}                                    ← 新增：中途流失的窗口不计入 N
```

- **重复采样与 shadow 合并触发**（同一轮既做 k 次采样又做对照），省成本
- **跨版本数据不可合并**：云端 API 的模型和 judge 会静默更新，必须打版本标签，否则 300 个窗口攒到一半就废了
- **窗口完整性**：用户中途流失的窗口不计入 N，否则有效样本被高估

## 5. 开闸判定（修订版）

| # | 条件 | 阈值 | 数据来源 |
|---|---|---|---|
| C1 | δ 的 CI 宽度 | < 0.3δ | 本地 |
| C2b | 反事实累计 ΔG1 的 CI 下界 | > −δ_harm（0.02/窗口） | 跨用户 |
| C3 | engagement → G1 的 AUC | > 0.55 | 跨用户 |
| C4 | 配对窗口数 | ≥ 300（由 ε 与可靠性反推） | 跨用户 |
| C5 | 离线 eval + 私有 holdout | 任一分桶不降 | 本地 |

任一条不满足 → 保持记录模式。**样本量不足按不通过处理。**

## 6. 仍然成立的前提

- 隐私：默认只落本地；上传需独立 opt-in；上传内容不含原文与事实层条目
- 显式反馈定位为守门信号，不作优化目标（采样偏差：会点的是一小撮人）
- 开闸判定设为定期动作（如每季度），不是"等有空再说"
- judge 是 LLM → 方差极大 → δ 必须实测，不能拍
