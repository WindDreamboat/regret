# 虚拟伴侣应用 — 需求简报与开发里程碑

## 一、产品定义

一款移动端虚拟伴侣应用，核心体验是**有记忆、有性格的日常聊天陪伴**。用户可以自由定制伴侣的性格、背景故事，伴侣通过 LAAP 认知架构维持持续的人格状态和记忆，对话中会体现情感变化（emoji/表情）。

---

## 二、已确认决策汇总

| 决策项 | 选择 |
|--------|------|
| 产品定位 | 有记忆、有性格的日常聊天伴侣 |
| 大模型 | 国内模型（DeepSeek 等云端 API） |
| 平台方案 | Web 端包装成 App（Capacitor） |
| LAAP 运行位置 | 端侧运行认知引擎（不跑模型推理） |
| 语言方案 | 把 LAAP 核心逻辑用 Rust 重写/移植 |
| V1 核心模块 | PSI认知循环简化版、自我模型、五层记忆精简、注意力与意识流、LLM适配层 |
| 用户账号 | 不需要登录（记忆存在浏览器本地） |
| 对话体验 | 文字 + 表情/emoji（增加情感表达） |
| 伴侣性格定制 | 自由定制（用户自定义性格、背景故事） |
| 技术背景 | 4年开发经验，主流语言基本都行 |

## 四、端侧 LAAP 移植策略

LAAP 官方实现约 92,000 行 Python + 17KB Rust 加速模块，包含 16 个认知模块。第一版建议用 **Rust 重写认知核心**（PSI 循环、情绪引擎、记忆索引、注意力），再通过 FFI 桥接到移动端：

| 平台 | 技术方案 |
|------|----------|
| Android | Rust → JNI → Kotlin/Java |
| iOS | Rust → C FFI → Swift |
| Web 包装 | Rust → WASM → JavaScript |

这样一套 Rust 核心可以复用到三个平台，避免三端各写一遍。

### 移植优先级

| 层级 | 是否适合端侧 | 说明 |
|------|-------------|------|
| 认知循环层 | 适合 | PSI 循环、需求驱动、注意力、自我模型、记忆索引、意识流调度 |
| 记忆与状态层 | 适合 | 工作记忆、情景记忆、语义记忆、向量记忆、自我模型持久化 |
| 大模型推理层 | 不走本地 | 仍然通过云端 API 调用，比如 DeepSeek |

### V1 优先实现的五个模块

1. **PSI 认知循环简化版** — 保留需求驱动、情绪状态、目标选择，先不做复杂自进化
2. **自我模型** — 记录伴侣的性格、关系状态、偏好、边界
3. **五层记忆的精简实现** — 先做工作记忆、情景记忆、语义记忆和向量记忆；程序记忆可以先简化
4. **注意力与意识流** — 决定当前对话里哪些记忆被唤起，哪些话题被放大
5. **LLM 适配层** — 负责把本地认知状态压缩成适合云端 API 的 prompt / 工具调用结构

像 RSI 自进化、AEvo 元编辑器、因果引擎 L3 反事实推理、代码自我修改这些，第一版可以先不做，或只在云端做实验性版本。

## 五、记忆存储（端侧本地）

| 记忆类型 | 存储方案 |
|----------|----------|
| 情景记忆 | SQLite（对话历史、时间戳、情绪标签） |
| 语义记忆 | SQLite（从对话中提取的事实、用户偏好） |
| 向量记忆 | 轻量向量索引（如 usearch Rust 库），存 embedding 后的记忆片段 |
| 自我模型 | JSON 文件持久化（性格维度、关系状态、边界设定） |

全部数据存本地，不上传云端，符合隐私优先的设计。

## 六、DeepSeek API 选型建议

DeepSeek 目前有两个主力模型：

| 模型 | 上下文 | 缓存命中输入 | 缓存未命中输入 | 输出 |
|------|--------|-------------|---------------|------|
| deepseek-flash | 1M | 0.05元/M | 1.5元/M | 4.5元/M |
| deepseek-v4-pro | 1M | 0.15元/M | 4.5元/M | 13.5元/M |

（空闲时段价格，周末/节假日全天空闲）

**建议 V1 用 deepseek-flash**：成本可控，支持 1M 上下文和 Tool Calls，配合 DeepSeek 的上下文缓存机制，多轮对话中重复的 system prompt 和历史记忆可以命中缓存，大幅降低成本。

---

## 七、Capacitor 包装

用 Capacitor 把 Web 前端打包成原生 App，可以上架应用商店，同时保留 PWA 能力。对于虚拟伴侣这种以对话为核心的应用，Capacitor 的体验已经足够好，而且后续如果需要调用推送通知、本地文件等原生能力也有扩展空间。

## 八、V1 功能范围

| 模块 | V1 实现 | V2+ 预留 |
|------|---------|----------|
| 人设定制 | 自由填写性格、背景、称呼 | 人设模板库 |
| 对话 | 文字 + emoji | 语音消息 |

| 主动关怀 | 基于 PSI 需求的简单触发 | 定时推送通知 |
| RSI 自进化 | 不做 | 云端实验 |

## 九、开发里程碑

### 迭代 1：认知核心骨架（约 1-2 周）

**目标**：跑通端侧 LAAP 核心最小闭环，不接 UI，先验证逻辑。

**交付物**：

- Rust 核心库（laap-core）基础框架
- PSI 循环简化版（需求 → 情绪 → 目标选择）
- 自我模型数据结构（性格维度、关系状态）
- 记忆接口定义（情景/语义/向量记忆的 trait）
- 单元测试覆盖核心逻辑

**验收标准**：

- 给定一段模拟对话输入，PSI 循环能产出情绪状态变化
- 自我模型能序列化为 JSON 并持久化到本地文件
- 记忆接口能通过 mock 数据完成写入和检索

> 这个阶段纯 Rust 开发，不涉及移动端绑定，方便快速迭代和测试。

---

### 迭代 2：记忆系统 + LLM 适配层（约 1-2 周）

**目标**：让认知引擎能"记住"对话，并组装 prompt 调用 DeepSeek。

**交付物**：

- SQLite 存储层（情景记忆、语义记忆）
- 轻量向量索引集成（usearch 或 hnswlib Rust 绑定）
- LLM 适配层：将认知状态 → DeepSeek API 请求
- DeepSeek API 客户端（含缓存 key 管理）
- 端到端 CLI 工具：输入一句话 → 输出伴侣回复

**验收标准**：

- 连续对话 10 轮以上，伴侣能引用之前的对话内容
- 自我模型中的性格设定能体现在回复风格中
- CLI 工具能稳定调用 DeepSeek API 并返回结果

---

### 迭代 3：移动端绑定 + 基础 UI（约 2-3 周）

**目标**：把 Rust 核心桥接到移动端，做出可交互的对话界面。

**交付物**：

- Rust → WASM 绑定（Web 端）
- Rust → JNI 绑定（Android）
- Rust → C FFI 绑定（iOS）
- React 前端对话界面（先做 Web 版）
- 人设配置页面（自由填写性格、背景、称呼）
- Capacitor 打包配置

**验收标准**：

- Web 版可在浏览器中正常运行对话
- 人设修改后，伴侣回复风格随之变化
- 对话历史在刷新页面后不丢失（IndexedDB 持久化）
- Capacitor 打包的 Android APK 可安装运行

---

### 迭代 4：情感表达 + 优化打磨（约 1-2 周）

**目标**：增加 emoji 情感表达，优化体验和性能。

**交付物**：

- PAD 情绪 → emoji 映射表
- 对话气泡中动态插入 emoji
- 记忆检索性能优化（向量搜索延迟 < 200ms）
- DeepSeek 上下文缓存策略调优
- 基础设置页面（清除记忆、导出对话等）

**验收标准**：

- 伴侣回复中情绪变化能通过 emoji 直观体现
- 长对话场景下响应延迟 < 2s（含 API 调用）
- Android 安装包体积 < 30MB
- 无明显崩溃或内存泄漏

---

## 十、开发时间线

| 阶段 | 时间 | 内容 |
|------|------|------|
| 迭代 1 | Week 1-2 | Rust 核心骨架 + 单元测试 |
| 迭代 2 | Week 3-4 | 记忆系统 + CLI 端到端验证 |
| 迭代 3 | Week 5-7 | 移动端绑定 + React 前端 |
| 迭代 4 | Week 8-9 | 情感表达 + 性能优化 |

如果 solo 开发且每天能投入 2-3 小时，大概 **2 个月**可以做出一个可用的 MVP。如果有更多时间或有人配合前端，可以压缩到 6 周左右。
