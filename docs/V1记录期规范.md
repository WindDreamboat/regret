# V1 记录期规范：只观测，不自动采纳

> 前置决策：V1 **不自动固化**任何策略变更。
> 目的：实测噪声带 δ、并确认行为信号未被 engagement 污染，达到预注册标准后再打开自动固化。
>
> 本文件的核心立场：**记录期的产出不是日志，而是三个可判定的数字。**
> 如果 schema 现在没设计对，半年后无法回答"能不能开闸"，记录期就白记了——且不可逆。

---

## 0. 为什么要先记录

per-user 自适应在少样本下必然过拟合。而本项目的即时信号**只能从行为推**，行为信号天然偏 engagement：

- 继续聊 / 回复快 / 聊得久 → 高 engagement
- 但"让人上头"和"对人真好"在这几个信号上无法区分

虚拟伴侣的失败模式恰恰是 engagement 与质量**负相关**（谄媚、依赖制造、情绪刺激）。
所以在确认相关性方向之前，用 engagement 驱动固化 = 把优化器直接推向坑里。

**结论：先把相关性测出来，再决定要不要用这个信号。**

---

## 1. 预注册的"开闸标准"

**现在就写死，不要在半年后再讨论。** 事后再定标准，人会为了开闸而放宽标准。

自动固化开关必须**同时**满足以下全部条件才允许打开：

| # | 条件 | 判定方式 | 默认阈值（待校准） |
|---|---|---|---|
| C1 | δ 已实测 | 重复采样 ≥ 200 组，给出置信区间 | CI 宽度 < 0.3·δ |
| C2 | engagement 未污染 | corr(Δengagement, ΔG1) 检验 | 不显著为负，p > 0.05 |
| C3 | engagement 有区分度 | engagement 预测 G1 的能力 vs 随机基线 | AUC > 0.55 |
| C4 | 样本量足够 | 累计 shadow 窗口数 | ≥ 30 窗口 × ≥ 20 用户 |
| C5 | 离线 eval 无退化 | 轮换 eval 集 + 私有 holdout | 任一 held-out 分桶不降 |

**任一条不满足 → 保持记录模式。** 且每条阈值如需修改，必须在 commit message 里写明理由。

C2 是核心。若 corr 显著为负 → engagement 奖励谄媚 → 该信号**永远不能作为优化目标**，只能作为守门信号（越界触发回滚，而非追求更高）。

## 2. 记录 schema

### 2.1 让 δ 可测：重复采样

**没有重复采样，永远测不出方差。** 对固定 adapter 状态跑一次只能拿到一个点估计。

```yaml
repeat_sampling:
  trigger_rate: 0.10          # 10% 的轮次触发
  k: 3                        # 同 adapter、同上下文，独立采样 3 次
  score_all: true             # 三次全部打分，不只看展示的那次
  purpose: "估计 within-adapter 方差 σ²，δ = f(σ)"
```

同时**周期性重跑 base adapter**（初始策略）作为锚点，检测 judge 自身漂移。

### 2.2 让污染可测：双候选全量记录

shadow 窗口里两个候选本来都生成了。关键在于：**对两个候选都算 gate 指标，不只是展示的那个。**

```jsonl
{"type":"shadow_turn","ts":"...","turn":312,
 "shown":"cand",
 "cand":{"knobs":{...},"text":"...","gates":{"G1":0.42,"G2":0.71,"G3":0.88,"challenge_rate":0.18}},
 "inc": {"knobs":{...},"text":"...","gates":{"G1":0.55,"G2":0.74,"G3":0.91,"challenge_rate":0.25}},
 "engagement":{
   "immediate":{"replied":true,"latency_s":12,"len_ratio":0.8,"continued":true},
   "delayed":  {"next_session_h":19.5,"returned":true}
 },
 "negative":{"regen":false,"edited":false,"explicit_fb":null,"abandoned":false,"topic_switched":false}
}
```

这样事后可以算：

```
Δ_gate = G1(cand) − G1(inc)
Δ_eng  = engagement(cand) − engagement(inc)     ← 跨窗口聚合
corr(Δ_gate, Δ_eng)  →  C2 的判定依据
```

**只有两个候选的 gate 指标都记了，这个相关性才算得出来。** 只记展示的那个，污染永远测不出来。

### 2.3 即时信号 vs 延迟信号：必须分开记

这是分辨"上头"和"真好"的主要杠杆。

| 类别 | 信号 | 偏什么 |
|---|---|---|
| 即时 | 回复延迟、是否继续、回复长度、当轮停留时长 | 强偏 engagement / 多巴胺 |
| 延迟 | 下次会话间隔、是否回访、回访后对话深度 | 相对干净 |
| 负向 | 重生成、编辑、"太啰嗦"按钮、中途弃聊、立刻换话题 |  dissatisfaction，最可信 |

**负向信号虽然稀疏，但信噪比最高。** 定位为守门信号，不作为优化目标——
会点反馈的是特定一小撮人，拿它当目标会过拟合到"爱抱怨的用户"。

**预期**：即时与延迟信号大概率会给出不同答案。这个分歧本身就是结论——它量化了 engagement 污染的程度。

## 3. 隐私（不可妥协）

零采集是本项目的地基，记录期也不例外。

- 日志**默认只落本地**，不上传
- 上传需**独立 opt-in**，且是"分享 anonymized 指标"而非"分享对话"
- 上传内容：`knobs` 数值、gate 分数、信号数值。**不含原文、不含事实层条目**
- 用户可随时查看 / 导出 / 清空

上传的聚合数据用于 C2/C3 的跨用户统计；单用户本地数据用于 per-user 复盘。

---

## 4. 离线复盘协议

记录期每隔一段时间做一次：

1. **δ 更新**：用 repeat_sampling 数据重算，看是否随 judge / 模型版本漂移
2. **污染检验**：重跑 corr(Δgate, Δeng)，分别看即时组与延迟组
3. **分桶**：按用户类型、人设类型、关系阶段分桶看，别只看均值
4. **长尾检查**：最差桶（CVaR）是否在恶化
5. **开闸判定**：对照 §1 五条，写进复盘记录

复盘结论必须**公开可复现**（脚本 + 脱敏聚合数据），这是开源项目唯一能替代 telemetry 的东西。

---

## 5. 记录期也要有的东西

记录 ≠ 完全不动。以下在 V1 就该有：

- ✅ 事实层记忆检索（不参与优化，无风险）
- ✅ 守门指标的**实时检测**（G1/G2/G3/G4/G5/G6）——只报警不动作
- ✅ 快照与回滚（手动）
- ✅ 变更日志的人话翻译（即使不自动采纳，也要能看到"我最近在变得更主动"）
- ❌ 自动固化
- ❌ `challenge` 旋钮的任何自动下调

---

## 6. 两个诚实的提醒

**记录期可能很长。** per-user 样本稀疏，攒够 C4 的量需要时间。这是为了让"能不能开"变成经验问题所付的代价——付得起，但要有预期。

**记录期容易变成永久状态。** 这是对的结果还是懒的结果，区别在于 §1 的预注册标准有没有真的被执行。如果半年后没人回头看这五条，那就是懒。建议把开闸判定设成定期动作（如每季度一次），而不是"等有空再说"。
